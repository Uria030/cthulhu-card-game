# E12 規格 — ACT 共用動作:揭穿傳說(線索轉傷害)

> **裁定**(Uria 2026-07-02):ACT 2 增加一條共用動作——花費 1 行動點,棄掉線索,每棄 1 線索對裂嘴女造成 1 點傷害;**整個團隊一回合只能做一次**。
> **設計意圖**:回應交叉測試報告「傷害競速,能查的死」——線索在 ACT2 獲得終局價值,調查型調查員全程有用。都市傳說主題自洽:知曉真相即傷害傳說。
> **工單**:Codex 實作,守燈人 review。日期碼 26070211。

## 規則正規化

| 項 | 規格 |
|---|---|
| 名稱 | 「揭穿傳說」(s06 文法;卡面句:【行動】棄掉任意數量線索:對深潛者裂嘴女造成等量傷害。全隊每回合限一次。) |
| 觸發資格 | 當前幕的資料含此共用動作(**資料驅動**,見下)且該幕目標敵人在場存活 |
| 成本 | 1 行動點 |
| 效果 | 棄 N 線索 → 對目標敵人 N 點傷害,**必中免檢定**(對齊 deal_damage 語意) |
| 限制 | 全隊每回合 1 次(回合開始重置) |
| 傷害管線 | 走既有敵傷路徑(enemyDamageAfterDefense/死亡詞綴/enemy_defeated → progressTick 勝利判定照常) |

## 實作要點

1. **資料驅動,不寫死關卡**:act 卡 schema 加 `shared_actions`(JSONB 陣列),元素如 `{ code: 'spend_clues_damage', target_variant: 'G1_deep_one_slit_mouth', ratio: 1, team_limit_per_turn: 1, name_zh: '揭穿傳說', narrative: '...' }`。migration + 雨夜的真相 ACT2 資料回填。引擎讀當前幕的 shared_actions 生成合法動作——未來任何幕都能配置同類動作。
2. **引擎語意注意**:引擎的線索是團隊池(`scenario.objectiveProgress`),不是個人持有——「你身上的線索」在現引擎 = 從團隊池棄。執行者選擇棄幾個(1 ~ 池內全部)。此偏差寫進規格註記,個人線索化留待規則書對賬時裁定。
3. **回合限制狀態**:scenario 層旗標(如 `sharedActionUsedThisTurn`),回合開始重置;多人一致性:AI 與玩家共搶同一次額度,後到者 intent 正常駁回+情境敘事。
4. **新 intent actionType**:`use_shared_action`,payload `{ code, amount }`;resolveIntent 統一裁決(AI/玩家同管線)。
5. **AI 接入**(同工單內完成,否則 AI 測不出新 meta):
   - `enumerateCandidates`:當前幕有此動作、池 >0、本回合未用 → 生成候選;價值 = min(池, 需求) × DMG_V(必中全額,對齊 P3 卡牌經濟);目標 = 幕目標時吃集火加成。
   - 指揮層第 3 層:kill 需求估算納入「池內線索可轉傷害」——這會改變梯隊分工(ACT1 多囤線索變成合理投資)。**注意:ACT1 翻面會花掉 2×人數線索,轉傷害用的是翻面後剩餘+ACT2 期新查的。**
6. **UI**:戰鬥板動作列在資格成立時顯示「揭穿傳說」鈕(含剩餘池數與本回合已用狀態);三段演出沿用。

## 驗收

- 引擎測試:資格判定/棄 N 傷 N/全隊一回合一次/回合重置/擊殺觸發勝利/池不足駁回。
- AI 測試:ACT2 有池時 AI 會用;與攻擊的價值排序合理(必中 N 傷 vs 期望 0.5 傷/AP)。
- sim:複跑交叉測試同隊表同種子(baseline 已封存)——預期全體勝率上升、線索型調查員勝率結構性改善;報告對照差異。
- 實測:UI 按鈕全流程。
