# M1 規劃 — 「一關玩到完整」

> **用途**:開發地圖(26070207)M1 站的完整施工規劃。目標一句話:**Uria 坐下來玩一場雨夜的真相,每個環節都和規則書寫的一樣。**
> **版本**:v0.1|**日期碼**:26070208
> **驗收**:①Uria 正式站實玩一場(自由順序行動/抽得到遭遇卡/看得見城主攤開池/完整結局文本)②sim 側 384 場勝率分布報告。
> **凍結紀律**:工作包①測試期間,關卡/城主/調查員 AI 引擎三凍結;⑤關卡調整必須排在①之後。

## 施工順序與依賴

```
① 64 人交叉測試+AI 修正輪(凍結期)──→ ⑤ 關卡收尾(解凍後)
② 回合流程重設計 ──┐
③ 神話卡攤開      ─┼─ 引擎側,可與①的跑分並行
```

## 工作包①|64 人交叉測試 + 調查員 AI 修正輪

**依據**:《調查員交叉測試計畫_20人勝率矩陣_v0_1_26070206》,規模從 20 人擴到 64 人。

### 前置工程(三件)
1. **泛用 AI 人格產生器**(shared 引擎):64 位新調查員沒有名冊 profile——從模板資料生成:名字/稱號取 DB、戰鬥風格取模板 proficiency、屬性已是 18 點完成態(自由配點空)、權重中性(P2 解耦後權重只是平手決勝)。名冊四人照舊。**順修既知矛盾:`proficiency_ids` 存 combat_styles UUID 而 play.ts 期望 code 字串**(後端統一)。
2. **sim 參數化**:隊伍四人模板 id + 種子從參數進;bootstrap 逐位快取本機(64 位各抓一次,不重複打 API)。
3. **批次跑分器**:讀組隊表→逐場跑→每場一行 JSONL(隊伍/種子/勝負/回合/毀滅/每人六項+倒地+對齊率+藍圖成形回合)→彙總腳本出矩陣。

### 測試設計
- 出場均衡隨機抽樣:**每位 ≥8 場、約 128 隊 × 3 固定種子 ≈ 384 場**,全本機零 API 寫入零 Gemini 成本。
- 全隊伍共用同一組 3 顆種子(消除種子運差);四人不重複;不刻意配平陣營。
- 鐵證偵探另跑 12 場當已知基準席。
- 強弱判定寫死:勝率信賴區間整段偏離全體平均才算「明顯」;中間段誠實標「無法區分」。

### 產出與後續
- 勝率榜(強/弱/無法區分)+ 每位診斷卡 + 陣營層彙總(**E 陣營補不補輸出卡在此出答案**)+ `effect_unsupported` 總清單。
- **弱因三分流 → 三張工單**:A 內容弱→生產線回鍋(Uria 終審參考)/B AI 不會用→調查員 AI 修正輪(預判集中在輔助型價值帳)/C 引擎不支援→效果碼補完清單(餵 M2)。
- AI 修正輪動工前提交修正主題給 Uria 過目(修正=引擎版本變動,測試數據就此封存為 baseline)。

### 風險
- 384 場約 4-6 小時本機時間 → 背景批次跑,喚醒紀律適用(完成才叫人)。
- 64 位是草稿態未經 Uria 終審——測試結果同時是終審的參考材料,不衝突。

## 工作包②|回合流程重設計

**依據**:Uria 2026-06-13 裁定(`project_turn_flow_redesign`):短休息=個人決定不跳階段;調查員同時/自由順序,無玩家→AI 固定先後。

### 現況錯誤(兩條)
1. 短休息呼叫 `setPhase('mythos')`——一人休息把全場推進神話階段。
2. AI 成批排在玩家之後行動——不是「同時」。

### 施工
1. **自由順序回合驅動**(`TestScenarioScreen`):調查員階段改為「所有站立調查員的行動權同時開放」——玩家任意時點行動;AI 計時器照既有節奏逐位跑,但玩家行動可插入任意兩個 AI 動作之間(現有計時器+訊號架構可承載,擴充「玩家行動不重置 AI 序列」的交錯邏輯)。
2. **衝突處理設計**:兩人同時搶同一資源(同一線索點/同一敵人補刀/同一倒地者救援)——引擎已是逐 intent 統一裁決(`resolveIntent` 序列化),天然無競態;需要補的是**體感層**:後到者的 intent 因狀態變化不再合法時,回饋敘事(「馬庫斯搶先一步壓住了傷口」)而不是冷冰冰駁回。
3. **短休息個人化**:短休息改個人狀態(本回合放棄行動換恢復,規則書 ch2 §2 語意),不觸碰全場階段;全員都結束(行動完或休息)才進神話階段。
4. AI 側配套:指揮層指派在自由順序下每席行動前已重算(P2 既有行為),無需改。

### 驗收
- 玩家在兩個 AI 行動之間插入行動成功;一人短休息,其他人照常行動;回合結束條件=全員行動完畢或休息。
- 回歸:既有 AI 計時器競態防護(Raviel BLOCK 修正)不得回退。

## 工作包③|神話卡攤開選用模型

**依據**:Uria 裁定(`project_keeper_mythos_open_hand`):整個 mythos_pool 攤在場上,城主每回合「選」1 張啟用,部分卡可重複使用,玩家可見產生壓力感。

### 施工
1. **schema**:mythos 卡加三欄——`reusable`(可重複)/`cooldown_turns`(冷卻回合)/`max_uses`(總次數上限)。MIGRATION + admin 編輯欄位。
2. **資料回填**:現有 12 張神話卡逐張定三欄值(設計層決定,回填方案先列表給 Uria 掃一眼再套——例:末日推進 reusable 無冷卻、深潛者增援 cooldown 2、瘋狂攫住 max_uses 3)。
3. **引擎**:`selectKeeperActivations` 從「牌堆抽選」改「攤開池選用」——資料驅動的可用性過濾(冷卻中/次數耗盡不可選),城主 AI 的戲劇曲線邏輯保留,選卡範圍改為當前合法池。
4. **UI**:戰鬥板城主區顯示攤開池全部卡面+每張的冷卻/剩餘次數狀態(玩家可見=壓力感的本體);三段演出沿用。
5. **城主 AI 升級**:選卡評分考慮冷卻機會成本(強卡冷卻中→次強卡頂上),沿用「風格即資料」不寫死。

### 驗收
- 戰鬥板看得見城主全部神話卡與狀態;冷卻/次數行為與資料一致;sim 回歸(城主行為變化在預期內,勝負結構不因 bug 崩壞)。
