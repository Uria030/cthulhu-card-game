## Part 1|帳號系統(E15:後端)

### Schema(新 migration,全部冪等)

| 表 | 欄位要點 |
|---|---|
| `players` | id/email(unique)/username(unique)/password_hash/**save_slots_max INT DEFAULT 2**/dead_count INT DEFAULT 0/retired_count INT DEFAULT 0/is_disabled/created_at/last_login_at |
| `player_sessions` 或 JWT | 比照既有 admin auth 模式(token+效期),玩家與 admin 權限體系分離 |
| `password_reset_tokens` | player_id/token_hash/expires_at(15 分鐘)/used_at——一次性 |
| `investigator_saves` | id/player_id/slot(1..save_slots_max)/template_id/**status: active·dead·retired**/campaign_progress JSONB(掛 3-1 的 CampaignProgress 跨章矩陣)/created_at/ended_at |

### API(/api/player/*)

- `POST /register`(email+username+password;密碼雜湊用 bcrypt/argon2,不存明文)
- `POST /login` → token;`POST /logout`
- `POST /forgot-password`(寄重設信;**回應不透露 email 是否存在**,防列舉)
- `POST /reset-password`(token+新密碼;token 一次性+15 分過期)
- `GET /me`(帳號+存檔格+死亡/退休履歷)
- `GET/POST /saves`(讀檔清單/開新檔);`POST /saves/:id/retire`(→retired,retired_count++,格子釋放);死亡由引擎結算寫入(→dead,dead_count++,格子釋放)
- 安全基線:登入與 forgot 加速率限制;reset token 雜湊入庫

### ⚖ 裁定點:Email 寄送服務選型

| 方案 | 成本 | 備註 |

| **Resend(建議)** | 免費額 3000 封/月 | API 簡單,Railway 友善 |
| SendGrid | 免費額 100 封/日 | 老牌 |
| 過渡方案 | $0 | 測試期不接信:後台(MOD-15)代發重設連結,正式上線前再接 |

建議:**先走過渡方案讓流程跑通,選型後只換寄送器**(寄信介面抽象成單一函式)。

## Part 2|主畫面存檔流(E16:前端)

1. **首次進入**:啟動畫面 → 未登入 → 登入/註冊畫面(含忘記密碼入口)。
2. **主畫面(大廳)改造**:登入後顯示**兩個存檔格**:
   - 格內有 active 存檔 → **讀檔**(帶 CampaignProgress 續戰役)
   - 空格 → **創新調查員**(接 E13 的 64 選 1 流程)
   - active 存檔 → 可**退休**(二次確認;記入履歷,格子釋放)
   - 死亡(創傷上限歸零永久死)由引擎自動結案入履歷
3. **帳號履歷顯示**:大廳一角顯示「已故 N 位・退休 M 位」(調查員檔案館/墓園的敘事雛形,本期只做數字)。
4. **進度遷移**:現行 localStorage 進度(測試資料)**不遷移,捨棄**——上帳號制即新開始(⚖ 若要保留再議)。
5. E13 的選人與自動組隊流程整個掛到「創新調查員」之下;AI 隊友不占存檔格(每局隨組)。

## Part 3|MOD-15 帳號管理(E17:後台)

- 新 admin 頁 `admin-account-manager.html`(掛 splash gate 慣例):
  - **帳號列表**:全部非 admin 帳號(搜尋/分頁/狀態/最後登入/死亡退休數)
  - **建帳號**(代註冊)、停用/啟用、**代發密碼重設**(過渡期的寄信替代)
  - **存檔管理**:看任一玩家的存檔格與 CampaignProgress;可改資源/XP/天賦點(測試調參用);可調該帳號 save_slots_max
  - 操作稽核 log(誰改了誰的什麼)
- 規範:MOD-15 入 regulation_index §2.7;操作手冊派工單目錄不涉(非生產線)。

## Part 4|M3 成長閉環串接(E18:整合)

引擎四件已完工(E4 XP/E5 天賦/E7 章節/E8 團隊精神),本包把它們掛上存檔:

1. 關卡結算 → XP/創傷/牌組變化寫進 save 的 CampaignProgress(**伺服器權威**:結算由 server 端點驗證入庫,client 不能自報)。
2. 整備模式讀寫 save(買升級卡/點天賦持久化)。
3. 章節串連的結局 flag 入 save → 下章分歧。
4. 死亡結案管線:永久死 → save status=dead → 主畫面格子釋放+履歷+1。
5. **驗收(M3 總驗收)**:同一帳號兩格檔——A 檔打完第一章帶成長進第二章;B 檔新開;A 退休後格子能再創;死亡入履歷。跨裝置登入讀得到同一進度(伺服器權威的直接證明)。
