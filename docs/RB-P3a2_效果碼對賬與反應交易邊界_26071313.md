### 已有專責管線，但不能視為 generic executor 已支援

| 效果碼 | 目前專責路徑 | 結論 |
|---|---|---|
| `spawn_enemy` | `encounters.ts` 遭遇效果 | 直接作為玩家卡 effect 仍 unsupported |
| `taunt` | `ruleEngine.resolveTaunt` intent | 直接作為 card effect 仍 unsupported |
| `stabilize_ally` | `ruleEngine.resolveStabilize` intent | 同上 |
| `seal_gate` | `gameProgress` ACT 目標 | 不是通用 effect 結算 |
| `cast_spell` | ruleEngine 依 arcane 卡路徑處理 | explicit effect code 尚未接 executor |

### 明確立債，不在 RB-P3a2 擴張

- 成長/永久改寫:`restore_hp_max`、`restore_san_max`、`transform`。
- 鍛造與製作:`forge_item`、`craft_item`。
- 書籍/遺跡內容容器:`read_book`、`research_relic`。
- 高階移動或定位:`jump`、`teleport`、`swap_position`、`place_enemy`。
- 額外牌組與戰術容器:`declare_stratagem`、`flip_card`、`direct_deploy`、`fast_play`、`target_other`。
- 跨人資源、復活:`transfer_resource`、`revive_ally`。

這些沒有出現在 E9 指定的四項，且尚缺必要狀態欄位或容器協議；不以偽實作消除 unsupported。

## 反應交易:待施工 v1 合約

規則書定義 reaction 為「條件觸發、玩家主動使用、不佔 AP」。要符合此語意，反應不能只在 action 完成後補一個按鈕，否則不能攔截傷害、檢定或對手動作。

v1 應建立 server/shared 同源的 `pendingReaction` 交易，至少含:

1. **可序列化的待結算 operation**:原 action 經合法性檢查後暫停，不能以 closure 保存續作。
2. **觸發語意**:先支持 `before_take_damage`、`before_take_horror`、`on_take_damage`、`on_take_horror` 與檢定結果；不要把任何 `reaction` 卡視為可任意打出。
3. **資格與隱私**:只對受影響調查員提供其私有手牌/額外牌組候選；其他玩家不取得卡名或效果。
4. **選擇與放棄**:玩家交 `play_reaction` 或 `pass_reaction`；多人 v1 不做逾時自動 pass，斷線才沿用現有 AI 接管規則。
5. **恢復與冪等**:反應結算或 pass 後，以同一權威 operation 恢復原 action；反應卡 instance ID 納入 `TurnState.triggeredReactions`，避免重送或重複使用。

這不是新玩法裁定，而是把 ch3/h03 已存在的「條件、零 AP、玩家主動」翻成多人不可競態的最低引擎合約。下一個施工切面必須先從一個可驗收的傷害/恐懼窗口開始，再擴到檢定與中斷對手動作。
