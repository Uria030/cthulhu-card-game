# MP-N1 交件：多人房間基建

署名：Nhalor @ Codex Desktop / UG

## 範圍與現況對賬

本包依 `docs/工作單_路線圖六步_26071301.md` 的 MP-N1 與 `M2M3規劃_帳號存檔與成長閉環_v0_1_26070505.md` Part 5 執行。

施工前現碼沒有房間服務、多人 state、WebSocket route，server 也尚未在 runtime 載入 shared rule engine。現有單機 `TestScenarioScreen` 完全未動。

本包只做 N1：房間生命週期、玩家 JWT 身分、server 權威 `resolveIntent`、WebSocket 同步、重送/亂序保護與 client transport。選人、ready、依關卡 bootstrap 建局、AI 補位、宣告制結束與大廳 UI 均保留 MP-N2。

## 變更摘要

1. 新增 shared 多人協議：房間快照、成員、認證、sequenced intent、權威結果、錯誤與關房訊息都由 `@cthulhu/shared` 定義。
2. 新增 `MultiplayerRoomService`：
   - 記憶體房間、六碼易讀房間碼、最多 4 席、開房/加入/離開/房主關房。
   - active room 持有唯一 `AuthoritativeGameState`；client 不可提交 state patch。
   - 每位玩家的 intent sequence 必須連續；相同序號回傳已快取結果但不再裁決，跳號拒絕並附目前快照。
   - 登入玩家只能操作自己的 investigator；`resolveIntent` 輸出的 `updatedAllies` 一律併回同一份 `investigators` snapshot。
3. 新增玩家 JWT middleware，從 MOD-15 路由抽出既有驗證邏輯，房間 REST 與 WebSocket 使用相同身分契約。
4. 新增 REST：`POST /api/multiplayer/rooms`、`GET /:code`、`POST /:code/join`、`POST /:code/leave`、`DELETE /:code`。
5. 新增 WebSocket：`GET /api/multiplayer/rooms/:code/ws`。連線後先送 `{type:'authenticate', token}`，成功後接收權威快照；accepted intent 廣播相同的 state + effects，rejected/duplicate 只回原 socket。JWT 不放 query string。
6. 新增 client `multiplayerTransport`，只負責送 intent 與接 server message，尚未接進單機 UI。
7. shared package 改為雙格式 runtime：Vite 使用 bundled ESM，Node authority server 使用 bundled CJS。shared build 不編譯 `.test.ts`，測試仍由 `tsx` 全量跑；root dev scripts 先建 shared runtime，避免乾淨 checkout 啟動時缺 dist。

## 自知風險與範圍外發現

1. N1 的房態依工單使用單一 server process 記憶體；部署重啟或未來水平擴展會清空房間，持久房態/跨 instance broker 不在 N1 範圍。
2. `activateGame` 是 server-only authority seam，供 N2 在選人/ready 驗證後以 bootstrap 建局；本包故意不提供 client state patch 或提前實作選人流程。
3. WebSocket 已測真實握手與認證；N2 仍需接大廳入口、兩裝置實玩、斷線 AI 代打與重連交還。
4. shared runtime bundle 使用工作區既有 Vite/esbuild toolchain。離線環境不能把 esbuild 提升為 shared direct dependency（pnpm 缺 package metadata），但 `pnpm install` 後 Vite 已保證其存在；build script 會在缺失時明確失敗。
5. shared production tsc 排除 `*.test.ts`，避免測試型別問題阻擋可部署 runtime；所有 shared test 檔仍由本次 20 檔 `tsx` 回歸執行。
