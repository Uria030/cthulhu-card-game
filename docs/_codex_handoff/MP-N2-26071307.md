## 變更摘要

1. shared 協議擴充：房間席位含 server 裁決的 template/ready；遊戲快照含真人控制映射、AI/human 控制權、宣告結束名單及每玩家 next sequence。新增 `declare_end`、AI 回合與階段訊息。
2. server 房間服務新增：64 選 1 互斥鎖、ready/start gate（v1 至少兩真人）、連線計數、斷線 AI 控制與重連交還、序號化宣告制、AI 回合同一 shared `runInvestigatorAITurn` 管線。
3. server 開局工廠：房主開始時以 server 內部 `app.inject` 讀既有 `/api/play/.../bootstrap`，組成真人 + E13 roster AI 補到四席的唯一 `AuthoritativeGameState`；卡片、敵人、風格、城主/怪物/進度資料只留 server runtime。
4. 全員宣告後，server 依序送神話階段訊息、城主選卡與結算、怪物啟動、恐懼、進度 tick、回合補給/開始，最後回到下一個調查員階段。測試涵蓋最小可重現的完整輪次。
5. WebSocket 正常關閉碼 `1000`（房間頁切換到戰鬥頁）不誤觸 AI；非正常中斷才會把該真人席交給 AI 執行回合。
6. client：大廳新增「邀請電報」入口；新房間頁含開/入房、房間碼、席位、64 選 1、ready、關卡選擇與房主開始；新多人戰鬥容器依 server 快照渲染地點、隊伍、資源、可用基礎動作、宣告結束與權威事件紀錄。

## 紅線檢查

- **多人一致性**：真人與 AI 都由 server `resolveIntent`/`runInvestigatorAITurn` 改唯一 state；`updatedAllies` 留在同一份 `investigators` snapshot，client 只顯示 server event。
- **計時器競態**：本包無 client timer 寫遊戲 state；斷線由 WebSocket close event 驅動，正常頁面交接與異常中斷分流。
- **冪等**：普通 intent 與 `declare_end` 共用每玩家連續 sequence/快取；快照提供 next sequence 供重連後續傳。
- **單機雙軌**：未改 `TestScenarioScreen`、`LobbyScreen` 的單機出發入口或既有單機 engine state。
