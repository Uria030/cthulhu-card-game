# MP-N2b 交件：多人權威結算補件

署名：Nhalor @ Codex Desktop / UG

## 範圍與目標

本包處理 `MP-N2-26071307.md` review WARN 的驗收第 4 項：多人關卡的 victory/defeat 不可只停在記憶體 state，必須由 server 對每位真人選定的 `investigator_saves` 做同一筆交易結算。

本包只補結算閉環與其選檔安全前提；MP-N2 仍未完成。多人 Modal 並行語意、三段 action/encounter Modal，以及完整單機操作 parity 都不在本包範圍。

## 變更摘要

1. 多人選人現在必須附上 active `investigator_saves` ID。server 以 `saveId + playerId + templateId + status=active` 驗證，拒絕 client 指向別人的或不同角色的存檔；ready 與開局工廠也要求每個真人席都有此 ID。
2. 新增 `scenario-settlement` service。將 E18 的既有單人 progress 計算抽為共用函式；多人結算在一個 DB transaction 中重新由 DB 讀 stage/chapter outcome、以 server flags 判定結局、逐席 `FOR UPDATE` 驗證存檔及角色 template，再寫入所有真人進度。任一席失效即 rollback，沒有半隊 commit。
3. 房間的 server-only state 保存 campaign flags、chapter outcomes、真人 `saveId` 對應和結算 callback。ACT/AGENDA 得出結局後先向 client 廣播 `pending`，交易成功才廣播 `saved`；失敗則廣播 `failed`，不向 client 假稱已保存。
4. 單人 `settle-scenario` route 改用同一個 progress helper，維持原本 E18 結算語意，避免單人和多人各自漂移。
5. 多人房間頁只允許玩家選取目前 active save 對應的調查員；戰鬥頁顯示權威結算狀態。

## 紅線檢查

- **存檔歸屬**：選人 endpoint 及最終交易都驗證 player/template/save 綁定；交易不信任 client outcome。
- **多人一致性**：所有真人存檔在單一 transaction 內結算；第二席失敗的回歸測試確認 `ROLLBACK` 且沒有 `COMMIT`。
- **狀態真實性**：server 推進以 runtime 的 campaign flags 和 chapter outcomes 判斷；client 只能收到 `pending/saved/failed` snapshot，不能自行標記完成。
- **單機雙軌**：E18 的單人結算改抽共用 helper，沒有改變單機 UI 或將多人 state 混回 `TestScenarioScreen`。

## 自知風險與下一包邊界

1. **MP-N2 驗收第 5 項仍未完成**：多人容器尚未接單機三段 action/encounter Modal，因此也尚未有「一人 Modal 未關不擋其他真人」的多 client UI 測試。
2. 多人容器的卡牌手牌、投入、傷害分配與其他單機操作尚未 parity；本包沒有將其誤標完成。
3. `saved` 是 DB transaction 成功的回報；若 server 在 commit 後、廣播前重啟，玩家重進需要由存檔畫面讀到已更新資料。房間本身仍是單 process 記憶體，這是 MP-N1 已知界線。
4. 本包未接觸城主數值、關卡配置或卡片資料，未跑平衡 sim；既有規則全測已覆蓋引擎回歸。
