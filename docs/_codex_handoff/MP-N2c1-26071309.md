# MP-N2c1 交件：多人本地演出與基礎操作容器

署名：Nhalor @ Codex Desktop / UG

## 範圍

本包是 MP-N2 驗收第 5 項的第一個可審子包。它不搬用單機 local-state 的 `TestScenarioScreen`，而是讓多人容器只以 server `snapshot + ResultEffect` 為資料來源，補足現有 shared 引擎已能裁決的基礎操作 UI。

**本包不宣稱 MP-N2 完成。** 遭遇卡的 server pending-interaction、指定玩家的選項回應與真正強制阻擋仍是 MP-N2c2。

## 變更摘要

1. 新增 authenticated `/api/multiplayer/rooms/:code/private-state`。它只回傳登入真人自己控制的調查員之手牌、場上資產及可操作 metadata；共享房間 snapshot 不加入手牌名稱／效果資料。
2. 多人戰鬥頁以 private state 呈現自己的手牌、可投入卡、打出／消費卡、場上資產行動；檢定型 action 會把已選 `commitCardIds` 連同 intent 送 server。
3. 多人頁補接 shared engine 已有的調查、移動、抽卡、拿資源、搜尋、挑釁、攻擊、閃避、穩定、盟友攻擊、打牌、消費、資產行動與宣告結束。按鈕只送 intent，沒有 client 自算 state。
4. 新增純 client `multiplayerCinematic`：每個 `intent_resolved` 在每個 client 形成自己的三段演出佇列。演出不使用 timer 寫遊戲 state；非指定玩家的遭遇只播放本地演出而不鎖操作。測試規定未來帶 `encounter_drawn/encounter_narrative` target 的事件，僅 target investigator 會被本地暫停。
5. private state endpoint 與 cinematic 都有 targeted test；既有多人 route/service 測試保持通過。

## 紅線檢查

- **server authority**：私人卡片資料由 authenticated endpoint 讀 server runtime；所有操作仍只送 sequence intent，snapshot/effects 才更新畫面。
- **多人一致性**：沒有在 client 端套用效果或寫 shared state；不同 client 可各自翻閱同一 action 的演出，不影響其他席位。
- **計時器競態**：演出以使用者本地「下一幕／收起」推進，不用 `setTimeout` 閉包改遊戲 state。
- **資訊邊界**：private state 依 room membership + player→investigator mapping 取值，沒有接受 client 指定 investigator ID。

## 範圍外與下一包

1. **MP-N2c2 必做**：目前多人 room 的 turn flow 尚未把 `encounter_cards` 的選項型互動抽成 server pending-interaction。因此本包的 target-only blocking 是已測的 client contract，但尚未有真實多人遭遇選項可以驅動它；不得以此宣稱第 5 項收尾。
2. 遭遇指定對象的 server lock / 選項 intent / 斷線 fallback / 多 client integration test 要一起在 N2c2 做，避免單機 `triggerEncounter` 直接複製造成雙 state。
3. `short_rest` 與 `commit_attribute_icon` 在 shared rule engine 仍是既有 stub，本包不顯示其按鈕也沒有補規則。
4. 完整單機 UI parity（手牌詳細卡面、傷害分配、整備等）不屬本子包；只接已可 server 裁決的基礎動作。
