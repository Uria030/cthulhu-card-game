# MP-N2c2 交件：多人遭遇 pending-interaction 與回合結束 queue

署名：Nhalor @ Codex Desktop / UG

## 範圍

本包承接 `MP-N2c1`，將多人遭遇從「只定義 client 演出契約」改為 server 權威的 pending-interaction。目標是落實 MP-N2 第 5 項的核心不變量：遭遇指定某位真人時，只有該席被暫停並能選項；其他真人能照常行動；斷線由 AI 接手；回合結束遭遇必須全隊依序處理後才能進補給／下一回合。

## 變更摘要

1. `AuthoritativeGameState.roundRuntime` 增加 server-only encounter deck、原始池與 trigger config；多人開局工廠從 trusted stage bootstrap 讀入，不讓 browser 提供遭遇資料。
2. 新增唯一 `pendingEncounter`：抽到選項型遭遇時，server 保存 card、target investigator 與 trigger context。共享 snapshot 只公開 target ID；private-state endpoint 只向 target 真人回傳卡名、敘事與選項。
3. 新 WebSocket message `resolve_encounter(sequence, encounterId, optionIndex)`。server 驗證連線席位、連續 sequence、pending ID、target 所屬與 option index，再以 shared `resolveEncounterOption` 寫唯一 scenario/investigator state；錯席不可代選。
4. target 有 pending 時，server 拒絕其一般 intent／declare end；其他真人不受限制。異常斷線後，既有 AI 接管會用 shared `chooseEncounterOption` 自動結算 pending，再繼續 AI 回合。
5. 神話後加入回合結束遭遇 queue：依活著的調查員逐席處理，AI 即時代選，真人依序 pending；最後一席結算後才執行 upkeep 與新回合。新 `encounter_triggered` server event 讓各 client 以既有本地三段演出播放抽卡時刻。
6. client 遭遇 choice 面板只依 private state 顯示；其按鈕只送 `resolve_encounter`，不在前端套用遭遇效果。

## 紅線檢查

- **權威與冪等**：card/deck/choice 都在 server runtime；choice 走每玩家連續 sequence 與 processed cache，client 無法指定 target 或直接寫遭遇結果。
- **多人並行**：server 只在 pending target 的 intent/declare gate 阻擋；同房其他真人仍能送 action。兩 socket 測試覆蓋此行為。
- **回合順序**：turn-end queue 在每位活著的調查員遭遇處理完之前不呼叫 upkeep／next turn；最後一席空 queue 會明確走 finish，而非卡在 mythos。
- **斷線**：非 1000 close 才執行 AI pending fallback；正常房間／戰鬥頁交接維持原來不代打規則。
- **計時器**：沒有新增 timer 寫 game state；遭遇抽取的 client 演出仍是本地按鈕推進。

## 已知邊界，請 reviewer 判定

1. 本包把 **player_action** 與 **turn_end** 兩條多人遭遇途徑接成 pending flow。多人 `advanceWhenEveryoneDeclared` 尚未把城主 `card_category=encounter` 與 spell chaos `headline` 兩條途徑轉入同一 queue；單機既有路徑不受影響。若 MP-N2 的「遭遇 Modal」要求四途徑全量 parity，請判為 WARN 並指定 N2c3；不可因本包測試全綠而隱瞞。
2. pending choice 現階段支援遭遇的一般 option resolver；法器破除／傷害分配等已有單機專用選擇窗尚未抽成多人 protocol，屬完整卡片互動 parity，後續由 RB-P3 或獨立包處理。
3. 本包未改城主數值、關卡配置或卡片資料，沒有調平衡。
