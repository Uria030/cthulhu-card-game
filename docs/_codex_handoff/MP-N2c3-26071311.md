# MP-N2c3 交件：多人遭遇四途徑收斂

署名：Nhalor @ Codex Desktop / UG

## 範圍

本包只處理 `MP-N2c2` WARN 指定的兩個缺口：城主 `card_category=encounter` 派發，以及施法混沌袋 `headline`。兩者均導入既有 server-authoritative pending encounter resolver；不調整城主數值、關卡設定或卡片內容。

## 變更摘要

1. 神話階段城主選出 encounter mythos card 時，server 將其 target/context 收入神話遭遇 queue；逐張以既有 `triggerEncounter` 觸發，真人 pending 選項完成後才續下一張，全部完成後才進回合結束 encounter queue/upkeep。
2. 玩家施法產生 `headline_drawn` 時，server 在該 intent 的權威結果後以 `chaos_headline` context 抽遭遇池，指定施法者。client 只收到既有 snapshot/effects/private-state，不能自報或自抽。
3. 為維持 queue 語意，`pendingMythosEncounterEntries` 保留 `undefined` 與空陣列的差異；只有真實神話 queue 才會走神話續跑，避免覆寫 turn-end queue。
4. 新增回歸：城主 encounter 在 rising tier 進 pending、選完後才進下一回合；arcane event 抽到 headline 進同一 pending resolver。既有 two-WebSocket resolver 測試（N2c2）持續全綠。

## 四途徑對賬

| 途徑 | 多人實作 | 互動結果 |
|---|---|---|
| player_action | `submitIntent` 依 action/location config | target pending，隊友可動 |
| turn_end | 神話後逐位 encounter queue | 全隊依序處理後才 upkeep |
| keeper_mythos | keeper encounter card 收入神話 queue | pending 完成後才轉 turn-end queue |
| chaos_headline | server 偵測 `headline_drawn` | 施法者進 pending |

## 紅線檢查

- **單一權威**：四條來源都只呼叫 `triggerEncounter` / `resolveEncounterOption`；deck、choice、效果皆在 server runtime。
- **並行**：pending gate 仍只鎖 target；神話/回合結束 queue 只控制 phase continuation，不阻擋其他不被指定的真人 action。
- **冪等與斷線**：choice 使用既有 sequence/cache；非正常斷線仍走 shared AI chooser，不留孤兒 pending。
- **凍結區**：沒有更動城主卡數值、關卡 encounter config 或資料庫內容。
