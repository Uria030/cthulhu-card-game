## 範圍與現況對賬

本包依 `docs/工作單_路線圖六步_26071301.md` 的 RB-P2 執行。

施工前對現碼：E2 已有 `selectKeeperActivations` 的攤開池、冷卻/使用次數過濾、冷卻機會成本、與 RB-P1-1b 的傳奇儲蓄協作；戰鬥板既有「點擊議程木牌」開啟完整城主神話卡池，並顯示冷卻與剩餘次數。因此本包沒有重寫既有選卡或另建重複 UI，而是補齊其三個缺口：持久狀態、資料回填、管理後台可編輯欄位。

## 變更摘要

1. `ScenarioState` 新增可序列化的 `keeperState`，持有城主能量、冷卻、已用次數與上次選卡資料；bootstrap 與測試關卡都建立初始狀態。
2. `TestScenarioScreen` 移除獨立的 React `useState` 城主狀態。神話階段與調查員階段的傳奇遭遇派發都將選後狀態寫回 `scenario`，使後續 `applyProgress`、遭遇結算與未來多人快照保留同一份資料。
3. 傳奇遭遇的 AI 目標自動結算可取得含新城主狀態的 scenario override，避免非同步 setState 競態把剛寫入的冷卻或使用次數覆蓋掉。
4. 新增 `MIGRATION_048`：冪等確保 canonical 欄位存在，並以 R3 規則回填原始 12 張神話卡的 `reusable`、`cooldown_turns`、`max_uses` 與 legacy alias。E20 傳奇遭遇卡是後加第 13 張草稿，保留原值、不納入本回填。
5. 城主卡管理頁新增「可重複使用 / 冷卻回合 / 本關卡使用上限」三欄，讀寫 canonical API 欄位；留空表示無冷卻或不限次數。
6. 補 bootstrap 與 `keeperAI` 回歸測試，確認開局有持久城主狀態，且無冷卻、無上限的末日推進會跨回合再次選用。
