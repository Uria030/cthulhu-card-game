## 交件內容

- 將 b1 的純 `PendingReaction` 接入多人 room service,但本子步刻意只涵蓋「遭遇選項內的 `deal_damage` / `hp_damage` / `deal_horror` / `san_damage`」。
- 遭遇選項改為「檢定/敘事 prelude + 可序列化 effect queue」:server 一項項套用;遇到符合 reaction 的傷害或恐懼時暫停，保留未跑完的 queue。
- 公開 snapshot 只含 `pendingReaction.targetInvestigatorId`;候選卡名、費用、效果 index 與原 operation 僅由 authenticated private-state 回給目標席。
- 新增 websocket 訊息 `resolve_reaction`, server 使用既有 player sequence、processed result、target gate 與 `TurnState.triggeredReactions` 做權威裁決。
- 無效 reaction 決定不消耗 sequence、不清 pending、不結算原 operation；目標可用同序號重試或 pass。這是 b1 review 指定的硬契約。
- 斷線後同一席轉 AI 時，AI 從合法候選挑最高減傷淨值並由相同 encounter continuation 續跑；沒有候選才 pass。
- `settleReactionOperation` 改走既有 `applyIncomingDamageToPlayer`,因此保留盟友分傷提示與 `direct` 不可轉移規則，避免 reaction 繞過 RB-P1 既有管線。
- `direct` 是否禁止 self-reaction 維持 b1 review 裁定:規則書未授權禁止，暫可反應;`direct` 仍只限制盟友分傷。
