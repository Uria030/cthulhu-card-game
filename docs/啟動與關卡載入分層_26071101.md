# 啟動與關卡載入分層

> 目的:遊戲內容成長後仍維持可預期的首屏時間,並明確區分本機素材與伺服器資料的讀取時機。

## 載入層級

| 層級 | 時機 | 本機素材 | 伺服器資料 |
|---|---|---|---|
| L0 應用殼 | HTML / JS / CSS 啟動 | Splash 石門、Logo SVG、字型與基礎樣式 | 無 |
| L1 啟動必要 | Logo 出現後的進度條期間 | 下一畫面的大廳底圖、出發地圖 | 公開關卡清單、公開調查員名冊 |
| L2 閒置預熱 | L1 完成、進入大廳前後的瀏覽器 idle 時間 | 劇情桌面、遊戲板、現行地點、議程、幕、Boss、實驗場圖像 | 無 |
| L3 玩家資料 | 玩家登入後 | 無 | `/api/player/me`、存檔、Creator 實驗場權限 |
| L4 關卡開局 | 已選調查員並點選關卡 | 該關已知的場景素材(若未命中 L2 cache) | 指定 stage + investigator 的 bootstrap、AI 隊友 bootstrap |
| L5 遊戲中 | 實際觸發內容時 | 後續章節或低頻卡面按需載入 | 存檔／結算寫回；卡片效果本身由本機共用引擎結算 |

## 分配原則

1. L1 只放「下一畫面一定用」且體積受控的素材；不得把全戰役美術塞進啟動進度條。
2. 公開、小型、跨畫面共用的 GET 可在 L1 暖快取；登入資料不得在玩家登入前讀取。
3. 依賴 `stageId`、調查員或隊伍組成的 bootstrap 必須留在 L4，避免讀到錯誤牌組或浪費請求。
4. L1 任一項逾時或失敗不得把玩家永久困在 Splash；目前 8 秒後放行，進入對應畫面時仍可重試。
5. API 快取失敗時必須清除 promise，下一畫面可以重新請求，不能保留毒快取。
6. 實驗場是 `sandbox`：可以讀正式牌組與規則資料，但不得寫回戰役進度、存檔或結局。

## 程式接點

- 載入清單:`packages/client/src/game/preloadPlan.ts`
- 載入執行器:`packages/client/src/game/preload.ts`
- 公開 GET promise cache:`packages/client/src/api.ts`
- 關卡 bootstrap cache:`packages/client/src/api.ts` 的 `fetchBootstrap`
- Creator 實驗場 manifest:`GET /api/player/card-lab`
