# 實玩回饋改動規劃：大廳與戰鬥盤面

> 日期：2026-07-12
> 狀態：規劃定稿，待拆工單施工
> 來源：Uria 於 iPad 實玩逐張截圖提出的介面回饋；本檔承接 `實玩缺陷修正批次1_26071103.md`，只記錄其後續未完成或改版的項目。
> 視覺權威：`C:\Ug\docs\GamePlan\DESIGN.md` 的 2026-07-12 暖調近黑白年代影像裁定。

## 1. 本批目標

讓玩家在大廳與戰鬥盤面上，不必猜測以下問題：

1. 自己選了誰、隊友是誰、以及每位調查員在場景中的位置。
2. 目前能在何處調查、可以移動到哪裡、哪些動作不可做。
3. 當前資源、牌組和棄牌狀態。
4. 關卡的 `Act` 與 `Agenda` 分別要玩家完成什麼、會如何失敗。

同時把視覺收斂為 1930 年代暖調近黑白的桌遊場景，移除會誤導角色身份或破壞場景一致性的具象人像。

## 2. 不可違反的設計裁定

### 2.1 不使用具象人像

- 遊戲畫面、背景、牆面裝飾與調查員呈現，不出現可辨認臉孔、真人肖像或固定人物照片。
- 大廳底圖不得烘焙固定入座人物；既有含有人像、相框肖像的大廳圖視為過渡素材，必須替換。
- 調查員以後續產生的匿名剪影與戰鬥棋子共同表示。角色更換時，大廳座位與戰鬥棋子都必須隨該調查員改變。
- 64 位正式調查員不做 64 張臉部肖像；應依職業可讀性分配到有限數量的匿名「剪影／棋子原型」，再套用玩家代表色。原型對應必須是穩定、可追溯的資料規則，不可由畫面隨機決定。

### 2.2 場景與互動的關係

- 大廳入口的感應區必須貼合實體物件，使用圓形或不規則貼合物件的 hit area，不得再以可見矩形框表示。
- 觸控、focus、active 狀態不能露出瀏覽器或矩形實體框線；只能顯示克制的年代感高光、亮度或物件回應。
- 戰鬥盤面的「不可執行」動作不顯示按鈕，不以灰化按鈕或空白預留位置誤導玩家。
- 所有新觸控入口在 iPad 橫向仍需至少 44 x 44px，且不得遮擋地點名稱、地點插圖、線索或棋子。

### 2.3 暫不使用的場景動效

- 先前加入的 React 閃電與壁爐火焰因表現錯誤而移除；本批不重做、不以替代特效補上。
- 之後若重啟動效，必須另立規格並先在桌面與 iPad 實測，不得與本批 UI 修正綁定。

## 3. 工作範圍

### A. 視覺憲法與共用角色資產

1. 在 `DESIGN.md` 補入「禁止具象人像」及「匿名剪影與棋子原型同源」規則，取代舊有可使用人物攝影／紀念照的描述。
2. 定義調查員視覺對應資料：
   - `investigatorId` 或職業分類 -> `silhouetteArchetype`。
   - `silhouetteArchetype` -> 對應的戰鬥 `pawnArchetype`。
   - 隊伍席位 -> 玩家代表色。
3. 先建立少量可覆蓋職業特徵的匿名原型，例如：持書／筆記者、醫療／照護者、工匠／勞作者、制服／執法人員、舞台／社交者、神秘／宗教者。命名以實作資料為準，不以 MBTI 作為畫面標籤。
4. 所有原型都使用暖調近黑白、同一鏡頭與光源語言；大廳剪影不可與底圖透視衝突，棋子則維持桌遊棋具的可辨識輪廓。

**驗收**：換玩家調查員或任一 AI 隊友後，大廳與戰鬥畫面同時更新對應原型；全畫面沒有具象臉孔或肖像。

### B. 大廳改版與入口校準

1. 重製不含固定人像的大廳底圖，保留書房／調查室的功能物件與 1930 年代暖調近黑白質感。
2. 將四個動態調查員剪影配置到可清楚辨識的座位；最左席永遠是玩家，其餘三席為隊友或 AI。
3. 逐一校準大廳入口物件的位置、文字與感應區；任何入口被背景物件遮住，或無法用合理 hit area 對齊時，回到重製底圖處理。
4. 改為無可見框線的圓形／物件形狀互動區，點擊時只顯示素材本身的回應；不要使用矩形按鈕框。
5. 維持大廳與存檔管理分流：大廳只組隊與出發，調查員存檔管理仍在獨立畫面。

**驗收**：1280 x 720、iPad 1024 x 768 與 iPad 橫向下，所有入口可點且不被遮擋；更換隊伍後四席即時反映；不出現焦點矩形或固定人物。

### C. 戰鬥盤面：地點、棋子與操作

1. 地點卡加高，保留圖片可視面積，避免操作入口蓋住地點插圖。
2. 調查員與怪物棋子移入所屬地點的圖片區域；不得佔用地點名稱、線索或操作區。多枚棋子需有固定排列規則，避免相互遮擋。
3. 線索指示固定放在地點卡最下方。
4. 地點行動改為兩顆圓形圖像按鈕：
   - 左下：放大鏡，「調查此地點」。
   - 右下：腳印，「移動到此」。
5. 僅在動作對目前玩家合法時顯示：
   - 可調查才顯示調查按鈕。
   - 可移動到目標才顯示移動按鈕。
   - 沒有合法動作時，該地點不留 disabled 按鈕。
6. 地點間連線必須持續可見；普通連線與受障礙／特殊條件限制的連線有不同線型，並與移動合法性一致。
7. 移除下方重複的「移動／調查」主操作列，保留抽卡、拿資源與階段必要操作；不能讓同一意圖有兩處入口。

**驗收**：每一個顯示的地點按鈕都能完成對應行動；不可行動時不顯示；棋子、線索、圖片、名稱與按鈕互不遮擋；可移動關係可由連線及腳印入口共同判讀。

### D. 戰鬥 HUD：調查員與玩家資源

1. 左下調查員狀態區保留角色狀態、生命、理智、手牌等即時資訊，改用與上方一致的舊木質素材框體，提升在暗背景上的辨識與質感。
2. 原左上的玩家資源面板移至右下，與系統按鈕合併為同一控制區：
   - 上段：資源、牌組張數、棄牌堆、除外區、額外牌組等可掃讀資訊。
   - 下段：系統按鈕，位置固定在此群組底部。
3. 右下資源控制區與左下調查員狀態區共用同一套老舊木頭、黃銅邊與低彩度材質語言；文字對比需通過可讀性檢查。
4. 右上戰役紀錄仍需完整顯示四位調查員摘要，不得漏掉第 4 位；展開後保留完整逐步行動紀錄。

**驗收**：任何回合都能看到玩家自身資源與五種牌區計數；四位調查員皆有摘要與完整 Log；HUD 不遮擋地點互動區或手牌區。

### E. 關卡開場的 Act／Agenda 說明卡

1. 關卡 bootstrap 完成、盤面顯示後、第一位調查員可操作前，彈出一次開場劇情卡。
2. 卡片同時顯示當前 `Act 1` 與 `Agenda 1` 的：名稱、敘事目的、玩家推進方向與失敗／升級的危險。
3. 關閉劇情卡後才開始第一個調查員回合；不得在背景偷偷消耗 AP、推進議程或派發 AI 行動。
4. 顯示使用既有劇情卡／紙張元件與正確的 `Noto Serif TC` 字體，不混用手寫斜體作功能性文字。

**驗收**：新開關卡必定先看到 Act 與 Agenda 說明；關閉前不會誤觸盤面；關閉後玩家狀態、Act／Agenda 計數與開局 bootstrap 資料完全一致。

## 4. 施工順序與切分

1. **規格與資料層**：補 `DESIGN.md`、調查員原型映射資料與共用元件契約。先完成此項，避免大廳與棋子使用不同分類。
2. **素材與大廳**：生成無人像底圖、匿名剪影，完成大廳換圖、座位疊圖與入口命中區。
3. **戰鬥盤面**：改地點卡結構、棋子層、合法動作顯隱與連線呈現。
4. **HUD 與開場流程**：搬移資源面板、套用木質框，加入 Act／Agenda 開場卡與回歸測試。
5. **跨裝置驗收**：桌面與 iPad 橫向各走一次大廳 -> 關卡 -> 第一回合 -> 一次移動／調查流程；以實際截圖復核遮擋與觸控命中。

## 5. 明確不在本批處理

- 不重做閃電或壁爐 React 動效。
- 不重做戰鬥規則、Act／Agenda 的資料內容或城主 AI 決策。
- 不替 64 位調查員個別繪製肖像。
- 不把存檔管理重新搬回大廳。
- 不因畫面需求改動既有玩家帳號、權限或卡片品質檢驗所邏輯。

## 6. 工程測試與交件 Gate

- Client：相關元件／流程測試、`tsc -b --pretty false`。
- Shared／Server：只有在開場流程或合法性資料契約變動時，才補對應回歸測試與型別檢查。
- 視覺：桌面 1280 x 720、iPad 1024 x 768、iPad 橫向各截圖核對；所有觸控入口至少 44 x 44px。
- 交件：依 `AGENTS.md` 工程協作 Gate，本機 commit、不 push、寫 handoff、送 Claude review；只有 review PASS 後才能 push。
