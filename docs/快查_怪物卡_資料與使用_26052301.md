## 二、資料組成(DB 表)

| 表 | 內容 |
|---|---|
| `monster_families` | 13 家族(code / name) |
| `monster_species` | 41 species(family_id FK / tier_min·max) |
| `monster_variants` | 73 隻(下詳) |
| `monster_attack_cards` | 136 張(方式庫,下詳) |
| `monster_status_descriptions` | 每變體 5 段 HP 階梯敘事(POST 時自動建) |

**variant 關鍵欄位**:`tier`(1-5)、`dc/hp_base/damage_*`(server `TIER_DEFAULTS` 自動補)、`spell_defense`(0-9)、`fear_type`(first_sight/per_round/on_reveal)、`movement_type`(ground/flying/dimensional/burrowing)、`keywords` JSONB、`ai_preference`、`weaknesses/resistances/immunities`(**禁 arcane**)、`phase_rules`/`legendary_actions` JSONB、**`move_pool` JSONB**(下詳)。
- `keywords` 必含:`function:*` / `threat_shape:*` / `family_subcategory:*` / `move_pattern:*`(精銳以上)/ `dissonance:*`(精銳以上)。

**attack card 關鍵欄位**:`defense_attribute`(玩家擲防的屬性)、`damage_physical/horror`、`damage_element`(6 元素,**禁 arcane**)、`inflicts_status`、**`special_effect`** JSONB、**`use_condition`** JSONB、`weight`、`narrative_attack/hit/miss_zh`、**`method_scope`**(universal/family/signature)、**`family_code`**。

## 三、★方式庫模型(MIGRATION_032/033,最重要)

怪物招式 = **跨怪共用的「方式庫」**,不是綁死單怪:
- 招式卡可**無主**(method_scope=`universal`,跨家族沿用)/ `family`(同家族沿用)/ `signature`(專屬不沿用)。
- 變體用 **`move_pool` JSONB** `[{code, weight, use_condition?}]` **引用**方式 code → 同一張招式可被多隻怪引用(沿用,不重造)。
- 出招邏輯 `move_pattern`:weighted 看 `move_pool[].weight`;conditional 看 `use_condition`;phase_based 看 `phase_rules.phases[].move_pool_ref`;ritual_sequence 看 `phase_rules.ritual`。

## 四、量產 driver(本機,不上 git)

`scripts/mod-agent-local/monsters/`
```
node run-batch-monster.mjs --post        # 怪物(BATCH_BRIEF 寫在腳本內,自己編輯)
node run-batch-attack-card.mjs --post    # 招式卡(同上)
```
- master:`master_monster_design.md` / `master_attack_card.md`。cost ~**$0.8/家族**。idempotent(預測 code 命中即 skip,不重燒)。
- **attack-card brief 可帶 `special_effect`/`use_condition`**(driver 直接寫入,目標機制當下到位、不事後補)。
- **brief 特殊語法**:`{reuse_code, target_variants, weight}` 跨怪沿用既有方式;`{universal:true, method_scope:'universal'}` 產 ownerless 通用招。
- 接線:signature 招 → 接該變體 move_pool;family/共用招 → 接該 species 全變體。

## 五★設計流程(已固化,每家族照走)

1. **入侵藍圖**:「這個神/家族怎麼入侵世界」,每階段 = 一個功能。
2. **功能 × 階層矩陣**:確認功能完整、跨召喚成本(雜兵便宜~巨頭貴)、呼應家族風格。
3. **monster brief**(function/目標先定)→ 跑 → QA(紅線/功能/結構)。
4. **attack brief**(帶 special_effect/use_condition)→ 跑 → QA(目標↔招式一致)。

## 六★設計準則(紅線)

- **目標先行**:每隻先定 `function`(7 種:combatant/agenda_pusher/environmental/controller/summoner/evolving/negotiable);**招式必須服務目標且有跡可循**(agenda→advance_agenda、controller→apply_control、summoner→summon、environmental→location_environment、combatant→造傷)。
- **家族功能完整性**:整池當完整入侵藍圖,別只堆 combatant。
- **位階紀律**:t1 雜兵單一肉搏/心智;agenda t1-3;controller/summoner t3+;environmental t1-4;頭目 5-8 招;巨頭 `cosmic_unique`+`legendary_actions`+`ritual_sequence`+不可擊敗。
- **defense ↔ threat_shape**(§3):**hp_combat → strength/agility/reflex(只此三,嚴守)**;mental/san_combat → willpower/intellect;environment → agility/perception/constitution;control → willpower/reflex/agility。
- **神秘鐵則**:`arcane` 永不出現在 weaknesses/resistances/immunities/damage_element(連萬象都不行)。
- **換皮判定**:歸別家族也合理 / 招池 90% 雷同 / 核心狀態與家族無關 = 換皮失敗。
- **命名虛標**:tier 1 禁「戰士/巨大/領主/祭司/之主/之王/本尊」等;巨頭用原典名。
- **黑名單(會被驗閘 warn)**:程式術語(精英/血量/理智值/tier/boss/HP/SAN)+ 程式詞中文同源 + **玩家(用調查員)** + 血腥詞(噴湧/內臟/腸子/殘肢)+ 口語(哥們/退後/哈囉)。

## 七、driver 防禦性 clamp(踩坑記錄)

- `movement_speed` 0/null → 1(server `||null` 會把 0 轉 null 違反 NOT NULL)。
- `spell_defense` clamp 0-9;`fear_type`/`movement_type` 非法值歸預設。
- `name_zh`/`name_en` > 64 字截斷(巨頭超長英文全稱會 22001)。
- variant POST / attack-card POST 端點都已回 `dbError` detail 方便診斷。
