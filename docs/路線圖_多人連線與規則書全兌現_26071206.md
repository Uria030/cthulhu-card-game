## 3. 軌二|多人連線(N1-N2,原 E19 v1 拆兩包)

### N1|房間基建(最大單一工程件,拆小先攻)
1. Server 權威房間:房間生命週期(開房/房間碼/加入/離開)+ 房內 shared 引擎實例(node 跑引擎已由 768 場 sim 實證)。
2. WebSocket 通道:client 送 intent、收狀態 + 演出效果;與現行單機 `resolveIntent` 序列化裁決同一管線(多人一致性紅線:全走 updatedAllies 模式)。
3. 依賴:E15 帳號(已上線)= 身分;不動現行單機路徑(單機 = 本機引擎照舊,雙軌並存)。
- 驗收:兩個 client 連同一房,狀態同步一致(先不管流程完整性)。

### N2|v1 兩人驗證(打完整局)
1. 開房 → 房間碼邀請 → 各自選調查員(64 選 1 互斥)→ ready → 開局;缺席 AI 補。
2. 宣告制結束(Uria 既裁):行動點歸零不自動結束、每位明確按「結束行動」、AI 跑完自動視為宣告、全員宣告進神話階段;UI 顯示未結束者。
3. 斷線 = AI 代打該席、重連交還(AI 與真人同意圖管線 = 架構紅利,零新機制)。
4. 大廳四座位接 R2:真人/AI/空位/ready 態。
- 驗收 = 目標②達成定義:**兩台裝置同房打完一關雨夜的真相**,中途一台斷線 AI 代打、重連交還,結算正確入各自帳號。
- 掛機逾時、觀戰、4 人同房 = v2,不擋本路線圖收官。

## 5. 施工順序與依賴

```
P1 體感債 → P2 神話攤開 → N1 房間基建 → N2 兩人驗證 → P3 卡片全規則 → P4 收斂對賬
                                   (P3 的獨立效果碼小項可在 N1/N2 review 空檔穿插)
```

- 排序理由:P1/P2 直接改善 Uria 當期的試玩品質(先讓試玩準確);N1/N2 是最大工程件,放中段盡早退風險、又不空等;P3 長尾可穿插;P4 必須最後(對賬要對「完工態」)。
- Nhalor 單線接包,一包一 Gate(handoff → 守燈人 review → push);視覺重製線(26071203)與本路線圖並行不互擋——素材歸 Terra,引擎歸本線,衝突時本線讓路(視覺是 Uria 試玩的眼睛)。
- **完成定義**:P4 + N2 雙驗收過 → 開「建立新關卡」(Story-to-Stage 生產線,MOD-06/07/08 派工單化,屆時另立計畫)。
